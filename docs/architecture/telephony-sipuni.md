# Телефония: Sipuni и разбор звонков ИИ

Каждая компания подключает **свой** аккаунт Sipuni и сама его оплачивает. CRM даёт коннектор:
звонки попадают в журнал сами, привязываются к клиенту и менеджеру, а ИИ расшифровывает и
оценивает отвеченные звонки.

## Подключение (директор)

1. Sipuni → Настройки → «Интеграция по API» → «Сгенерировать» ключ. Номер кабинета — там же.
2. CRM → Настройки компании → «Телефония: Sipuni»: номер кабинета, ключ, номер компании,
   язык звонков, как Sipuni пишет запись (моно или стерео), внутренние номера сотрудников.
3. CRM один раз показывает **адрес для событий**. Его вставляют в Sipuni → Настройки → API →
   «События на АТС» → «Подключить услугу». Потеряли — «Выдать новый адрес» (старый перестаёт
   работать).

API: `GET/PUT/DELETE /api/v1/telephony/sipuni/` (`integrations.manage`). Ключ хранится
зашифрованным и не возвращается; токен адреса хранится только как SHA-256.

## Что происходит со звонком

```
Sipuni ──событие «положили трубку»──▶ POST /api/v1/telephony/sipuni/events/<компания>/<токен>/
  └▶ журнал звонков (один раз на call_id): направление, номер клиента, менеджер по внутреннему
     номеру (нет в списке — тот, кто подключил), клиент с этим телефоном, длительность, ссылка
     на запись
  └▶ отвечен и есть запись → ИИ:
       скачать запись из Sipuni → PUT /v1/audio → call.transcribe.v1 (ru или ky; стерео —
       подписи «Менеджер»/«Клиент») → удалить аудио в AI Platform → call.review.v1 по чек-листу
       компании → балл 0–100 считает CRM (выполнено 2, частично 1, пропущено 0; «не к месту» не
       считается)
```

- Sipuni не подписывает события: доступ даёт только секретный токен в адресе. Неизвестная
  компания и неверный токен дают одинаковый 404. Ответ на валидный адрес — всегда
  `{"success": true}`, иначе Sipuni приостанавливает отправку.
- Резюме звонка (`call.summary`) теперь строится по расшифровке, если она есть.
- Звонок по кнопке из CRM идёт через Sipuni (`/callback/call_number`), если у менеджера есть
  внутренний номер.
- Разбор: `GET/POST /api/v1/ai/calls/<id>/analysis/` (POST — заново, например на кыргызском);
  чек-лист: `GET/PUT /api/v1/ai/calls/checklist/` (менять — `company.settings.manage`).

## Ограничения и что проверить на живом аккаунте

- Форматы событий и запросов взяты из doc.sipuni.com; на настоящем аккаунте ещё не проверены.
  Поле с номером заказа в ответе `call_number` в документации не названо.
- Звонок привязывается к **клиенту** по телефону; к лиду — нет (журнал звонков не поддерживает
  ссылку на лид).
- Кыргызская речь: нужна модель, дообученная на кыргызском (AI Platform, `docs/GPU_DEPLOY.md`);
  до проверки носителем языка расшифровка помечается как черновая.
- Клиентов нужно предупреждать о записи разговора (настраивается в Sipuni).
